# 保証を破るパターン

テストが通っているのに振る舞いの変化を検出できない型を並べる。各パターンには、そのパターンに当たったときにどう反例を作るかを添えた。パターン名を報告するだけでは足りない。監査対象のコードでの具体的な反例に落とすところまで行う。

## アサーションが値を見ていない

`expect(result).toBeTruthy()`、`expect(result).toBeDefined()`、`expect(() => f()).not.toThrow()` のように、成否だけを見て値を見ていないアサーションを指す。

反例の作り方は、要求される値とは違うが truthy な値を返す実装を書く。空配列を返すべき箇所で `[1]` を返す実装、`{ ok: true }` を返すべき箇所で `{ ok: false }` を返す実装が通過することを示す。

`not.toThrow` は例外が出ないことしか保証しない。戻り値が全面的に誤っていても通過する。

## モックの呼び出しを検証している

`expect(mockSave).toHaveBeenCalledWith(x)` のように、依存が呼ばれたことを検証して、呼んだ結果として何が起きたかを検証していないテストを指す。

反例の作り方は、依存を正しい引数で呼びながら戻り値を無視する実装、あるいは呼んだあとに結果を捨てる実装を書く。モックの呼び出し検証はそれを検出しない。

このパターンは、モックが実物と違う振る舞いをする場合にさらに弱くなる。実物が失敗を返す条件でモックが成功を返すなら、そのテストは実運用で起きる経路を1つも通していない。反例として、実物の失敗レスポンスを挙げる。

## テストが実装をなぞっている

実装の計算式や分岐構造をテスト側でも書き直しているテストを指す。期待値をハードコードせず、テスト内で計算して比較している場合がこれに当たる。

反例の作り方は、実装とテストの両方に同じ誤りを入れる操作を示す。実装の式を変えるとテストの式も同じ方向へ変わるため、誤りが検出されない。期待値を手で計算した定数に置き換えるべきだと指摘する。

スナップショットテストも同じ性質を持つ。出力が変わったことは検出するが、変わった後の出力が正しいかは判定しない。スナップショットを更新すれば通るため、要求命題の保証にはならない。

## 検証の時点がずれている

非同期処理の完了前にアサーションが走っているテストを指す。`await` の欠落、`setTimeout` への依存、`waitFor` の条件が緩い場合が該当する。

反例の作り方は、処理を遅くしても通過することを示す。あるいは処理を最初から実行しない実装が通過することを示す。アサーションが実行された時点で対象がまだ初期状態なら、そのテストは初期状態を検証している。

このパターンは間欠的な失敗として現れることが多い。落ちる頻度が低いため保証されていると誤解されやすい。

## 前提が正常系に固定されている

フィクスチャが1種類しかなく、境界値と異常系がそのテストの経路に入らない構成を指す。分岐の一方だけが実行され、他方は書かれているだけになる。

反例の作り方は、実行されていない分岐を空の実装に置き換えて、テストが通ることを示す。到達しない分岐は保証されていない。

カバレッジのレポートで行が緑になっていても、その行が到達しただけでアサーションがその行の効果を見ていない場合がある。行の到達と保証は別である。

## 例外の型と内容を見ていない

`expect(() => f()).toThrow()` のように、例外が出ることだけを検証して型もメッセージも見ていないテストを指す。

反例の作り方は、要求と無関係な例外を投げる実装を書く。引数の検証に失敗して投げるべき箇所で、実装のバグによる `TypeError` が出ても通過することを示す。呼び出し側が例外の型で分岐する場合、この差は実害になる。

## 状態の後始末が保証を消している

前のテストが残した状態に依存して通っているテスト、あるいは共有状態を書き換えて後続のテストの前提を壊しているテストを指す。

反例の作り方は、そのテストだけを単体で実行すると落ちることを示す。あるいは実行順を変えると結果が変わることを示す。他のテストに依存して通っているテストは、単独では何も保証していない。

## 検出のための読み方

上のパターンを探すときは、次の順で読む。

1. アサーションの行だけを抜き出す。テスト名と `describe` を隠して読む
2. 各アサーションが、どの値のどの性質を固定しているかを書く
3. 固定されていない性質を挙げる。そこが反例の候補になる
4. 候補ごとに、その性質だけを壊す実装を書けるか試す。書けたら確定した欠落である

3 で候補が挙がらない場合、そのテストは強い。強いテストも報告する。何が保証されているかを示すことが監査の半分である。
